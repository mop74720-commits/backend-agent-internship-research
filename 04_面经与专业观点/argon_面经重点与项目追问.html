面经重点与项目追问指南

面试官不会孤立考察组件名词，而是沿着“业务职责 → 架构取舍 → 极端故障与评测验证”逐层追问。本页将 99 份面经提炼为后端 5 大问题簇与 Agent 5 大问题簇，并直接映射到可核读的项目源码模块。

99 份面经样本构成

全文核读 92 份、部分核读 7 份。其中严格近期（2025–2026）工程实习 14 份、AI Infra 实习对照 1 份、明确实习但未标年份 48 份。

后端追问核心主线

围绕真实请求链展开：本人负责边界 → SQL/索引与缓存并发回源 → MQ 幂等/补偿与死信 → 线上容量估算与排障验证。

Agent 追问核心主线

围绕可控执行闭环展开：多步编排必要性 → RAG 召回重排与工具 Schema 约束 → 持久化恢复与写操作沙箱 → 留出集回归评测。

阅读口径统一说明（全文适用，各条目不再重复标注）：① 原帖提问源自作者面后回忆或复盘转述，用于定位考察机制，非逐字录音或企业统一题库；② “准备深度”为本报告归纳的工程自查目标，不代表原作者现场完整答出；③ 项目与面经按技术主题对照，仅标有候选人编号（如 CV21、CV28、CV31、CV05）的项目存在候选人本人归属关系。

01 · 后端面试核心追问

后端面试：从“用过组件”追问到“边界与故障处理”

后端实习面试极少停留在概念背诵，往往从简历上的一句描述切入，连续追问数据流转、并发冲突、异常恢复与线上指标验证。

B1先讲业务约束和本人职责，再讲技术栈

核心判断：能解释为什么需要这些模块、自己负责哪段链路，比把组件名写满更能承接后续追问。

面试官怎么追问（问题簇与原题）

考察切入点：需求、使用者、数据与请求链路；自己负责和复用的范围；业务字段、数据访问方式与选型之间的关系；替代方案的代价。

💡 面试官追问时的三步递进答题骨架（B1）

第一步：讲清约束与职责先用 30 秒画清请求入口、核心状态流转和上下游依赖，明确指出哪几个类/接口是你本人从零写的，哪部分复用了团队脚手架。
第二步：拆解并发/失败边界主动挑出业务中最痛的 1 个约束（如高并发争抢、跨服务状态同步），对比当时考虑过的备选方案及放弃原因（如开发成本 vs 一致性代价）。
第三步：给出量化验证证据给出可核查的交付物证据（如单测覆盖、上线后修复过的 1 个真实 Bug 或压测对比数据）。

B2数据库与缓存准备到访问路径和并发边界

💡 面试官追问时的三步递进答题骨架（B2）

第一步：讲清约束与职责报出核心表的数据量级（如千万行）、主键与联合索引结构，说明高频 SQL 是如何命中覆盖索引或避免回表与文件排序（Using filesort）的。
第二步：拆解并发/失败边界讲清 Redis 与 MySQL 的读写配合模式（如 Cache-Aside + 延迟双删或 Binlog 异步淘汰），重点剖析并发回源（Single-Flight vs 分布式锁）和缓存失效瞬间的边界。
第三步：给出量化验证证据用 EXPLAIN 执行计划指标（rows、key、Extra）或压测 QPS/P99 曲线证明优化实效，并坦诚指出单机合并与跨节点互斥的适用边界。

B3消息和事务的重点是失败窗口

核心判断：顺序消息、异步编排与幂等要结合业务约束解释；引入MQ后，仍需交代重复投递、事务提交和补偿失败。

💡 面试官追问时的三步递进答题骨架（B3）

第一步：讲清约束与职责画出异步链路的完整状态机（如：已创建 → 待投递 → 处理中 → 成功/失败补偿），说明为什么该场景必须异步化（削峰、解耦或长耗时任务）。
第二步：拆解并发/失败边界拆解三大故障窗口：① 生产端 DB 事务成功但 MQ 投递失败（用本地 Outbox 表解决）；② Broker 重复投递（消费端用业务唯一键 + 状态条件更新解决，绝不能先查后写分离）；③ 消费持续失败（重试退避 + 死信队列告警）。
第三步：给出量化验证证据说明积压监控指标（Consumer Lag）以及当下游服务不可用时的降级与重放恢复演练结果。

02 · AGENT工程面试核心追问

Agent 面试：从“调用模型”追问到“可控执行与评测闭环”

Agent 工程岗重点考察候选人是否真正解决过检索噪声、工具失败、状态中断、权限隔离与评测回归等工程问题，同时保留服务端并发与代码实现考察。

💡 面试官追问时的三步递进答题骨架（A1）

第一步：讲清约束与职责先回答“为什么不用单次 Prompt 或简单 Workflow”：指出任务存在动态分支、多轮外部信息依赖或长上下文污染，必须引入状态图编排。
第二步：拆解并发/失败边界讲清架构控制权：由确定性代码控制状态机流转、重试上限与停止条件，大模型仅负责节点内的局部推理或结构化路由决策。
第三步：给出量化验证证据给出与单 Agent / 单次调用基线（Baseline）在相同测试集上的成功率、Token 消耗与耗时对比。

A2RAG与效果指标要能回到数据和对照

核心判断：切块、检索、幻觉和任务评测要能说明测什么、如何比较。当前深入提问的部分来源事件年未知，作为高相关选读保留。
